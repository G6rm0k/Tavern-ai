# Аудит проекта + идеи для новичков

Полный разбор кода (`server/index.js`, все модули `public/js/`, `start.bat`, README)
с точки зрения человека, который **вчера купил ПК** и не знает слов «npm», «терминал»,
«base URL» и «токен».

Документ состоит из двух частей:
1. **Баги** — то, что уже сломано или сломается. Порядок = приоритет.
2. **Идеи** — что добавить, чтобы новичок дошёл от «скачал» до «болтаю с персонажем»
   без единого вопроса и без падений.

# ЧАСТЬ 1. БАГИ

## 🔴 Критические (потеря данных / приложение перестаёт работать)

### 1.1 Смена пароля молча не работает

`public/js/app.js:387` отправляет `password` в профиль, но
`server/index.js:291` его выкидывает:

```js
const allowed = ['displayName', 'username', 'bio', 'avatar', 'banner'];
```

Пользователь вводит новый пароль → видит «Сохранено!» → перезапускает → не может войти
старым (он думает, что старый уже не действует) и не может новым (он не сохранился).

**Хуже**: если наивно добавить `password` в `allowed`, всё сломается ещё сильнее.
Ключ шифрования выводится из пароля (`deriveKey(password, user.id)`,
`server/index.js:29`). Сменил пароль — **все старые чаты, персонажи и промты
расшифровываются в пустую строку навсегда**.

**Чинить так:** отдельный эндпоинт `POST /api/auth/password` с проверкой старого пароля,
который перед сменой перешифровывает все данные пользователя старым ключом → новым.
Пока этого нет — просто убрать поле «Новый пароль» из UI, чтобы не врать.

---

### 1.2 Перезапуск сервера превращает чаты в мусор `enc:...`

`keyStore` — это `Map` в оперативке (`server/index.js:27`). JWT живёт 90 дней.
Значит после любого рестарта сервера (закрыл окно и открыл заново, обновление,
кнопка «Рестарт сервера» в админке) складывается такая картина:

- токен ещё валиден → пользователь считается залогиненным;
- ключа шифрования нет → `GET /api/chats` отдаёт `enc:a3f1:9b2c:...` вместо текста;
- в чате видны кракозябры, **и они же уходят в LLM как контекст** → модель отвечает бредом;
- системный промт персонажа тоже `enc:...` → персонаж полностью ломается;
- отправка нового сообщения перезаписывает файл, смешивая шифрованное и открытое.

Пользователь не понимает, что произошло, и думает, что программа сломалась.
Он не догадается, что лечится это выходом и повторным входом.

**Чинить:** в `verifyToken` (или в отдельном middleware) — если `keyStore.get(userId)`
пустой, отдавать `401` с кодом `NEED_RELOGIN`, фронт показывает экран
«Введи пароль, чтобы расшифровать данные» (без полного логаута, чтобы не терять состояние).

---

### 1.3 Повреждение `chats.json` = приложение кирпич

`writeJSON` (`server/index.js:207`) — это обычный `fs.writeFileSync` **всего файла целиком**.
Файлы: `characters.json` ~28 МБ, `chats.json` ~27 МБ. Перезапись происходит **на каждое
отправленное сообщение**.

Отключили свет / закрыли окно в момент записи → файл обрезан → `readJSON` бросает
исключение → **каждый** запрос к API падает с 500 → приложение мертво, восстановления нет,
бэкапов нет.

**Чинить (обязательный минимум):**
- атомарная запись: `writeFileSync(file + '.tmp')` → `renameSync(tmp, file)`;
- ротация бэкапов: перед записью копировать в `file.bak1/.bak2/.bak3`;
- при старте: если JSON не парсится — автоматически поднять последний живой `.bak`
  и сказать об этом в консоль и в UI.

---

### 1.4 27 МБ синхронной записи на каждое сообщение

Тот же `writeJSON`. `fs.writeFileSync` **блокирует event loop**: пока пишутся 27 МБ,
сервер не обрабатывает ничего, включая идущий стрим ответа. На ноутбуке с HDD
это заметные подвисания, и чем дольше пользуешься — тем хуже. Плюс `readJSON`
парсит эти же 27 МБ на **каждый** запрос.

**Чинить (по возрастанию усилий):**
- быстрый костыль: `JSON.stringify(data)` без `null, 2` (минус ~30 % объёма) + дебаунс записи;
- нормально: один файл на чат — `data/chats/<id>.json`;
- правильно: `better-sqlite3`, одна таблица сообщений, запись одной строки вместо файла.

---

### 1.5 Аватарки лежат base64 внутри JSON

Импорт с Chub.ai кладёт всю PNG-картинку как data-URL прямо в запись персонажа
(`server/index.js:470`). Отсюда и 28 МБ. Последствия:

- `GET /api/characters` **на каждой загрузке страницы** отдаёт браузеру мегабайты base64;
- список персонажей на слабом ПК открывается секундами;
- каждое сохранение персонажа переписывает эти мегабайты.

**Чинить:** сохранять в `data/avatars/<id>.png`, в JSON держать только путь,
раздавать через `express.static`. Разово мигрировать существующие при старте.

---

### 1.6 XSS через имя персонажа с Chub.ai

Персонажи качаются с **чужого сайта**, то есть их имена и описания — недоверенные данные.
Они вставляются в `innerHTML` без экранирования:

- `public/js/app.js:170-188` — `_chatsHtml()`: `c.characterName` и превью **текста последнего сообщения**;
- `public/js/app.js:215-227` — тот же список на главной;
- `public/js/chat.js:59` — имя в шапке чата;
- `public/js/app.js:410-416` — `displayName` и `bio` в профиле;
- `public/js/app.js:518` — `toast()` вставляет через `innerHTML` **текст ошибки от провайдера**;
- `public/js/characters.js:103` — `value="${c.name}"`: имя с кавычкой ломает форму редактирования.

Персонаж с именем `<img src=x onerror="...">` выполнит код на странице.
А на странице в этот момент лежит **расшифрованный API-ключ** (`Settings.data.providers[].apiKey`),
который можно тихо отправить куда угодно.

**Чинить:** `escHtml` уже есть в `characters.js:2` — вынести в общий модуль и применить
во всех местах. Отдельно `toast()` перевести на `textContent`.

### 1.7 Публичные персонажи в принципе не читаются другими

`encryptCharacter` шифрует описание и системный промт **всегда**, ключом владельца.
А `GET /api/characters` (`server/index.js:358`) расшифровывает только свои:

```js
.map(c => (key && c.ownerId === userId) ? decryptCharacter(c, key) : c)
```

Значит любой персонаж с `visibility: 'public'` виден остальным как
`описание: enc:8f2a...`, а в чате он получает `enc:...` вместо системного промта.
**Функция «Публичный» не работает вообще** — она только создаёт битые карточки.

**Чинить:** либо не шифровать поля публичных персонажей (шифровать при переключении
в private, расшифровывать при публикации), либо честно убрать переключатель из UI.

---

### 1.8 Пресет «Anthropic» не заработает никогда

`server/index.js:305` и `public/js/settings.js:11` предлагают
`https://api.anthropic.com/v1`. Но прокси всегда стучится в
`${baseUrl}/chat/completions` с заголовком `Authorization: Bearer ...`
(`server/index.js:619-626`).

У Anthropic другой протокол: `POST /v1/messages`, заголовки `x-api-key`
и `anthropic-version`. Ответ — всегда ошибка.

Новичок выбирает знакомое имя из списка, вставляет купленный ключ, получает
непонятную ошибку и решает, что программа кривая.

**Чинить:** либо адаптер для Anthropic на сервере, либо убрать пресет и оставить
подсказку «Anthropic → подключай через OpenRouter/VseGPT».

## 🟡 Средние (работает, но неправильно или опасно)

### 2.1 «Экспорт данных» выгружает API-ключи открытым текстом

`public/js/settings.js:374` пишет в файл `this.data` целиком, а там
`providers[].apiKey` уже **расшифрован**. Файл падает в «Загрузки» без единого
предупреждения. Пользователь пересылает его «для бэкапа» — и отдаёт свой платный ключ.

Плюс кнопка врёт: называется «Экспорт данных», а персонажей и чаты не экспортирует.

**Чинить:** галочка «включить API-ключи (осторожно!)», по умолчанию выключена;
и добавить в экспорт персонажей и чаты (см. идею 8.1).

---

### 2.2 Открытый прокси и SSRF на `/api/chat/stream`

Эндпоинт (`server/index.js:590`) **вообще не проверяет токен** и ходит по любому
`provider.baseUrl`, который пришёл с клиента. Сервер слушает `0.0.0.0`
(`server/index.js:910`), README предлагает открывать его с телефона по локалке.

Итог: любой в той же Wi-Fi-сети (или кто угодно, если проброшен порт) может заставить
сервер сходить на `http://localhost:<что угодно>` и получить ответ. Также без авторизации
доступны `/api/search` и `/api/users/:username` — они отдают список всех аккаунтов сервера.

**Чинить:** `verifyToken` на `/api/chat/stream`, `/api/search`, `/api/users/*`;
запретить в `baseUrl` приватные диапазоны (кроме явно разрешённых `localhost:11434` /
`localhost:1234` для Ollama и LM Studio).

### 2.3 «Перегенерировать» на первом сообщении стирает чат

`public/js/chat.js:353-371`: сначала `messages.slice(0, idx)`, потом поиск последнего

и следующее же сохранение запишет пустой чат.

**Чинить:** проверять наличие user-сообщения **до** обрезки.

### 2.4 «Удалить все чаты» вешает приложение

`public/js/settings.js:383` удаляет чаты по одному, последовательно, и каждый

### 2.5 Автовыход через 30 минут без предупреждения

Черновик сообщения теряется. Для локального приложения на домашнем ПК это скорее

**Чинить:** переключатель в настройках (варианты: выкл / 30 мин / 2 часа), по умолчанию

### 2.7 Порт занят → чёрное окно со стектрейсом

Ни `EADDRINUSE`, ни любой другой ошибки старта не обрабатывается. Если 3000-й порт

### 2.8 «Рестарт сервера» создаёт процесс-призрак

`server/index.js:856-870` запускает `spawn(..., { detached: true })` и убивает себя.

### 2.9 Кнопка «загрузить модели» почти всегда молча падает

`public/js/modelloader.js:42-66` дёргает `/models` **напрямую из браузера**.
Большинство провайдеров (OpenAI в том числе) не отдают CORS-заголовки для чужих

# ЧАСТЬ 2. ИДЕИ

Отсортированы по тому, насколько они помогают именно **новичку на новом ПК**.

## 3. Установка без единой команды

### 3.1 ⭐ Один `.exe` — главное решение

Пока для запуска нужен установленный Node.js, половина новичков отвалится на этом шаге.
Варианты, от простого к сложному:

- **Node SEA** (Single Executable Application, штатная возможность Node 20+) — собирает
  сервер и `public/` в один `wesaid.exe`. Node пользователю больше не нужен вообще.
- **`pkg` / `nexe`** — то же самое, проще в настройке, работает и для Mac/Linux.
- **Tauri или Electron** — полноценное окно приложения с иконкой, без браузера.
  Tauri даёт ~5 МБ вместо ~120 МБ у Electron.

Сценарий мечты для новичка: скачал один файл → двойной клик → открылось окно.
Ноль терминала, ноль вопросов.

### 3.2 `start.bat` 2.0 — если exe пока далеко

- Node не найден → предложить установить **автоматически**:
  `winget install OpenJS.NodeJS.LTS` (winget есть во всех Windows 10/11 из коробки),
  с понятным текстом «Сейчас скачается Node.js, это нужно один раз, ~30 МБ».
- Проверять именно **версию** (`>=18`), а не факт наличия.
- Никогда не закрывать окно при ошибке — всегда `pause` и человеческая подсказка.
- Открывать браузер **после** того, как сервер реально ответил (пинговать в цикле),
  а не через фиксированную секунду.
- Всё на русском (сейчас — на английском).

### 3.3 `start.command` и `start.sh`

Mac и Linux сейчас не поддержаны совсем.

### 3.4 Ярлык на рабочий стол

При первом запуске предложить создать ярлык с иконкой. Новичку не надо помнить,
в какой папке лежит `start.bat`.

### 3.5 Значок в трее вместо чёрного окна

Свернуть, а не закрыть; в меню — «Открыть», «Перезапустить», «Выход».
Заодно решается проблема 2.8: становится понятно, как остановить программу.

### 3.6 Автозапуск вместе с Windows

Галочка в настройках. Приложение всегда «просто есть».

### 3.7 Кнопка «Обновить» в настройках

Проверять GitHub Releases, показывать что нового, обновляться в один клик.
Новичок никогда не сделает `git pull`.

## 4. Первый запуск: от «скачал» до «болтаю»

Сейчас после регистрации человек упирается в форму с полями
**«Base URL» / «API Key» / «Модель»**. Для него это три бессмысленных слова.
Кнопка «Пропустить» ведёт в приложение, где любое сообщение выдаёт ошибку.
Это главная дыра в опыте новичка — всё остальное вторично.

### 4.1 ⭐ Визард вместо формы

**Шаг 1. «Как хочешь пользоваться?»** — три большие карточки, без жаргона:

| Карточка | Что под капотом | Кому |
|---|---|---|
| 🆓 **Бесплатно, из интернета** | OpenRouter, бесплатные модели `:free` | Большинству |
| 💻 **Бесплатно, на своём ПК** | Ollama / LM Studio, ничего никуда не уходит | У кого мощный ПК |
| 💳 **У меня уже есть ключ** | текущая форма | Кто в теме |

**Шаг 2. Пошаговая инструкция со скриншотами.** Для OpenRouter буквально:
«1. Открой openrouter.ai → 2. Войди через Google → 3. Нажми Keys → Create Key →
4. Скопируй и вставь сюда». Кнопка «Открыть сайт» рядом.

**Шаг 3. ⭐ Кнопка «Проверить».** Реальный тестовый запрос и понятный вердикт:

- ✅ «Всё работает! Модель ответила за 1.2 сек»
- ❌ «Ключ неверный — проверь, что скопировал целиком»
- ❌ «На балансе нет денег»
- ❌ «Нет интернета»

Сейчас узнать о неправильном ключе можно только отправив сообщение персонажу
и получив сырую ошибку API.

**Шаг 4.** Имя, язык, тема.

### 4.2 ⭐ Автопоиск локальных моделей

При первом старте тихо пингануть `localhost:11434` (Ollama) и `localhost:1234`
(LM Studio). Нашли — сразу показать:

> 🦙 Обнаружена Ollama с моделью `llama3.2`. Подключить в один клик?

Полностью бесплатно, без регистраций и ключей. Идеальный вход для новичка.

### 4.3 Демо-режим без ключа

Пока провайдер не настроен — не блокировать приложение, а дать «болванчика»,
который отвечает заготовками. Человек сразу видит, как выглядит чат, ради чего всё это,
и уже осознанно идёт за ключом. Сейчас он видит пустой экран и ошибку.

### 4.4 Персонажи из коробки

5–8 готовых, доступных сразу после регистрации: Ассистент, Переводчик,
Репетитор английского, Собеседник, пара ролевых. Пустой экран — худшее первое впечатление.

### 4.5 Тур по интерфейсу

30 секунд подсветок: «здесь твои персонажи», «здесь ищешь новых», «здесь настройки».
Пропускается одной кнопкой.

### 4.6 Честное предупреждение про пароль

На экране регистрации: «Этим паролем шифруются твои переписки. **Восстановить его
невозможно** — забудешь, потеряешь все чаты». Плюс кнопка «Сохранить в файл».
Сейчас человек об этом не узнает до момента потери.

## 5. Понятность интерфейса

### 5.1 Спрятать жаргон

«Top P», «Top K», «Контекст», «Макс. токены» — новичку не нужны и пугают.
Оставить наверху три пресета словами (уже есть — это хорошо), остальное убрать
под раскрывающийся блок **«Продвинутые настройки»**. Возле каждого — «?» с
объяснением на человеческом:

> **Температура** — насколько персонаж непредсказуем.
> Ниже = отвечает чётко и по делу. Выше = фантазирует и удивляет.

### 5.2 ⭐ Человеческие ошибки вместо сырых

Сейчас текст ошибки от провайдера показывается как есть — новичку это ничего не говорит.
Нужен маппинг с **кнопкой действия прямо в уведомлении**:

| Код | Текст для человека | Кнопка |
|---|---|---|
| 401 | Ключ не подошёл. Проверь, что скопировал его целиком | «Открыть настройки» |
| 402 / `insufficient` | На балансе кончились деньги | «Пополнить» |
| 429 | Слишком много запросов подряд, подожди минуту | — |
| 404 `model` | Такой модели нет. Выбери другую | «Выбрать модель» |
| `ECONNREFUSED` localhost | Ollama не запущена | «Как запустить» |
| нет сети | Нет интернета | «Повторить» |

### 5.3 Индикатор состояния

В шапке: 🟢 `gpt-4o-mini` — подключено / 🔴 нет связи. Видно с первого взгляда,
почему не работает.

### 5.4 Счётчик расходов

Примерная стоимость сообщения и сессии в ₽/$. Плюс мягкое предупреждение
«за сегодня потрачено ~$0.40». Новичок панически боится «случайно потратить много» —
и правильно делает.

### 5.5 Читаемость

Размер шрифта (README его уже обещает!), межстрочный интервал, ширина колонки,
режим «как в книге». И **разрешить зум** — сейчас он запрещён глобально.

## 6. Надёжность — «чтобы без багов»

Это прямой ответ на «самое главное удобство и без багов». Порядок работ:

1. **Атомарная запись + бэкапы + автовосстановление** (баг 1.3) — иначе всё остальное неважно.
2. **Не терять ключ шифрования при рестарте** (баг 1.2).
3. **Экранировать HTML везде** (баг 1.6).
4. **SQLite или файл-на-чат** (баги 1.4, 2.4).
5. **Аватарки на диск** (баг 1.5).
6. **Автосохранение черновика** сообщения в `localStorage` — сейчас теряется при
   автовыходе, перезагрузке, случайном закрытии.
7. **Кнопка «Стоп»** для генерации.
8. **Экран краша вместо белого** — если фронт упал, показать «Что-то сломалось» и
   кнопку **«Скопировать отчёт для GitHub»** (версия, браузер, стек, последние действия).
   Тогда в issues начнут приходить полезные баг-репорты, а не «не работает».
9. **Логи в `data/logs/`** с ротацией.
10. **Оффлайн-детект** и очередь на отправку.

## 8. Фичи

### 8.1 ⭐ Настоящий бэкап в один клик

- **«Скачать всё»** — персонажи + чаты + настройки в один `.zip`,
  с галочкой «включить API-ключи» (по умолчанию выключена).
- **«Восстановить из файла»** — сейчас восстановления нет вообще.

Для новичка это ещё и способ переехать на другой ПК без понимания, где что лежит.

### 8.2 Несколько чатов с одним персонажем

`Chat.startWith` (`chat.js:12`) всегда открывает существующий чат — начать новую
историю с тем же персонажем невозможно. Плюс переименование чатов.

### 8.3 Свайп-варианты ответа

Как в SillyTavern: стрелочки ‹ 2/3 › для перебора вариантов ответа.
Сейчас «перегенерировать» **удаляет** старый ответ — сравнить нельзя, вернуться нельзя.

### 8.4 Персона пользователя

Кто такой `{{user}}`: имя, возраст, описание себя. Сейчас подставляется только
`displayName`. Это заметно улучшает качество ролевых диалогов.

### 8.5 Лорбук / World Info

Ключевые слова → автоподстановка в контекст. Одна из главных фич SillyTavern,
которой здесь нет совсем.

### 8.6 Память длинных чатов

Контекст — 20 последних сообщений, всё остальное персонаж забывает.
Решение: автосаммари старой части чата и подстановка её в системный промт.

### 8.7 Голос

- **Озвучка ответов** — Web Speech API, встроен в браузер, бесплатно, ~20 строк кода.
- **Надиктовка** — тем же API.

Для новичка это самая «вау» функция при минимальных затратах.

### 8.8 Быстрая смена модели прямо в чате

Выпадашка в шапке + «перегенерировать другой моделью» («а как ответит другая?»).
